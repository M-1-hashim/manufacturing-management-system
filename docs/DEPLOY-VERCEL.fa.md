# راهنمای دیپلوی روی Vercel ▲

این راهنما برای استقرار **سامانه مدیریت تولید (ManufacturingERP)** روی پلتفرم **Vercel** تهیه شده است.

**چرا Vercel؟** رایگان شروع می‌شود، سرور Node آماده می‌دهد (نیازی به «Setup Node.js App» در cPanel نیست)، HTTPS خودکار، دامنهٔ رایگان، و با هر `git push` خودکار دوباره دیپلوی می‌شود.

---

## 📋 پیش‌نیازها

| مورد | توضیح |
|------|-------|
| اکانت Vercel | رایگان — با همان اکانت GitHub خودتان ثبت‌نام کنید → [vercel.com/signup](https://vercel.com/signup) |
| اکانت GitHub | پروژه از قبل به مخزن `M-1-hashim/manufacturing-management-system` متصل است |
| دیتابیس MySQL | فقط برای استقرار واقعی الزامی است — **برای دمو می‌توانید کلاً حذفش کنید** (بخش بعدی) |

> ⚠️ **مهم‌ترین نکته:** تفاوت اصلی Vercel با هاست اشتراکی این است که فایل‌سیستم فقط‌خواندنی است؛ به همین دلیل در استقرار واقعی دیتابیس باید حتماً MySQL بیرونی باشد و برنامه از قبل برای همین آماده شده (حالت «استقرار وب»). برای دمو، اصلاً دیتابیس لازم نیست ⬇️

## 🎬 حالت دمو — بدون دیتابیس، لاگین ساده (سریع‌ترین راه)

اگر می‌خواهید فقط یک لینک آنلاین برای نمایش سیستم به مشتری/مدیر داشته باشید و سراغ دیتابیس نروید:

**هیچ `DATABASE_URL` تنظیم نکنید** — برنامه در زمان بیلد خودش تشخیص می‌دهد و کامل در «حالت نمایشی» بالا می‌آید:

- ورود با یک حساب ساده: `admin` / `admin123` — **بدون نیاز به هیچ دیتابیسی**
- کل سیستم (۱۳ ماژول) با دیتای نمونهٔ واقع‌گرایانه کار می‌کند
- دیتا و تغییرات هر بازدیدکننده فقط در مرورگر خودش ذخیره می‌شود — بین افراد مشترک نیست و به سرور کاری ندارد
- روی صفحهٔ ورود و کنار نام سیستم، برچسب «حالت نمایشی» دیده می‌شود

**تغییر نام کاربری/رمز دمو** (اختیاری) — دو متغیر محیطی در Vercel بسازید:

| نام | مثال |
|-----|------|
| `NEXT_PUBLIC_DEMO_USERNAME` | `demo` |
| `NEXT_PUBLIC_DEMO_PASSWORD` | `رمز-دلخواه-شما` |

> ⚠️ اگر رمز دلخواه تنظیم کنید، راهنمای ورود دیگر روی صفحهٔ ورود نمایش داده نمی‌شود — رمز را به مخاطب دمو خودتان بگویید.

> 💡 **بعداً خواستید نسخهٔ واقعی شود؟** فقط `DATABASE_URL` را به متغیرهای محیطی اضافه کنید → Deploy مجدد — همان لینک، این‌بار با دیتابیس واقعی. برگشت به دمو = حذف متغیر و Deploy مجدد.

## گام ۱ — آماده‌سازی دیتابیس MySQL (دو گزینه)

### گزینهٔ الف — استفاده از MySQL هاست اشتراکی فعلی (رایگان/بدون هزینهٔ جدید)

اگر همین حالا دیتابیس MySQL در cPanel دارید و دیتای سیستم داخلش است، می‌توانید **همان را** نگه دارید:

1. وارد **cPanel** شوید → بخش **Databases** → **Remote MySQL®**
2. در قسمت *Access Hosts* آدرس `%` را وارد کنید → **Add Host**
   - این کار اتصال از سرورهای Vercel را مجاز می‌کند (Vercel IP ثابت ندارد)
   - ⚠️ امنیت به رمز قوی کاربر دیتابیس وابسته می‌شود — رمز حتماً قوی انتخاب کنید
3. رشتهٔ اتصال را بسازید:
   ```
   mysql://نام‌کاربری:رمز@نام‌هاست:3306/نام‌دیتابیس?connection_limit=5&connect_timeout=10
   ```
   نمونهٔ واقعی:
   ```
   mysql://setab_mfguser:Kj8#mP2$vL@server370.web-hosting.com:3306/setab_mfgdb?connection_limit=5&connect_timeout=10
   ```
   - نام‌هاست: همان چیزی که در cPanel برای ورود به phpMyAdmin/پنل استفاده می‌کنید (معمولاً آدرس سرور، **نه** `localhost`)
   - رمز داخل URL: اگر کاراکتر خاص (`@ # ? &`) دارد باید encode شود؛ ساده‌تر: رمز بدون این کاراکترها بسازید

### گزینهٔ ب — دیتابیس MySQL ابری (پیشنهادی برای پایداری بیشتر)

| سرویس | پلن رایگان | نکته |
|-------|-----------|------|
| **Aiven for MySQL** | ✓ (۱ گیگ) | سریع، TLS خودکار، انتخاب منطقهٔ اروپا |
| **TiDB Cloud (Serverless)** | ✓ | سازگار با MySQL |
| **Railway / Clever Cloud** | محدود | ساده و سریع |

بعد از ساخت دیتابیس، رشتهٔ اتصال را از پنل سرویس بردارید. برای سرویس‌های TLS‌دار (Aiven/TiDB) معمولاً پارامتر اضافه لازم نیست؛ اگر خطای SSL گرفتید `&sslaccept=accept_invalid_certs` را موقتاً اضافه کنید.

> 💡 **کدام گزینه؟** اگر الان نسخهٔ هاست اشتراکی کار می‌کند و دیتا همان‌جاست، گزینهٔ الف را انتخاب کنید تا نیازی به انتقال دیتا نباشد.

### انتقال دیتای فعلی به دیتابیس جدید (در صورت نیاز)

1. از نسخهٔ فعلی (وب یا دسکتاپ) وارد شوید: **تنظیمات → پشتیبان‌گیری → «خروجی JSON»**
2. روی استقرار جدید Vercel با اکانت `admin` وارد شوید
3. **تنظیمات → پشتیبان‌گیری → آپلود فایل و بازیابی** → همان فایل JSON را بدهید

## گام ۲ — ایمپورت پروژه در Vercel

1. وارد [vercel.com/new](https://vercel.com/new) شوید
2. **Import Git Repository** → مخزن `manufacturing-management-system` را انتخاب کنید
   - اگر مخزن در فهرست نیست: *Adjust GitHub App Permissions* → دسترسی به مخزن بدهید
3. در صفحهٔ *Configure Project*:
   - **Framework Preset:** به‌طور خودکار `Next.js` شناسایی می‌شود — دست نزنید
   - **Build Command / Install Command:** از فایل `vercel.json` خوانده می‌شود — دست نزنید
     (بیلد خودش `prisma generate` با اسکیمای MySQL ابری را اجرا می‌کند)
4. **قبل از اولین دیپلوی** به بخش **Environment Variables** بروید (همان صفحه، پایین) و دو متغیر را وارد کنید ⬇️

## گام ۳ — تنظیم Environment Variables

| نام | مقدار | توضیح |
|-----|-------|-------|
| `DATABASE_URL` | رشتهٔ اتصال MySQL از گام ۱ | برای **استقرار واقعی الزامی** — اگر تنظیم نشود، برنامه در حالت دمو (بخش بالا) بالا می‌آید |
| `SESSION_SECRET` | رشتهٔ تصادفی ۳۲+ کاراکتری | فقط برای استقرار واقعی — کلید امضای نشست‌ها، بسازید با: `openssl rand -base64 48` |

برای استقرار واقعی هر دو را برای محیط‌های **Production, Preview و Development** تیک بزنید → **Add**

> 💡 نمونهٔ کامل و توضیح پارامترها در فایل `.env.example` پروژه هست.

## گام ۴ — منطقهٔ اجرای سرور (پیشنهادی)

**Settings → Functions → Function Region** → نزدیک‌ترین منطقه به کاربران:

- `dub1` (دبی) — بهترین برای افغانستان/ایران اگر در فهرست بود
- `fra1` (فرانکفورت) — پیش‌فرض تنظیم‌شده در `vercel.json` (پایدار و خوب)

## گام ۵ — Deploy!

1. دکمهٔ **Deploy** را بزنید — بیلد ۲–۴ دقیقه طول می‌کشد
2. بعد از اتمام، آدرس مثل `manufacturing-management-system.vercel.app` داده می‌شود
3. آدرس را باز کنید → صفحهٔ ورود سیستم نمایش داده می‌شود

### چه اتفاقی در اولین اجرا می‌افتد؟

- برنامه به‌طور خودکار به MySQL وصل می‌شود
- **جدول‌های گمشده خودکار ساخته می‌شوند** (۱۹ جدول) — نیازی به اجرای دستی migration نیست
- اگر دیتابیس خالی باشد، حساب `admin` با رمز پیش‌فرض `admin123` ساخته می‌شود
- اگر دیتابیس قبلاً از هاست اشتراکی پر بوده، همان دیتا را می‌بینید — هیچ‌چیز جابه‌جا نمی‌شود

> ⚠️ **بلافاصله بعد از اولین ورود، رمز `admin` را عوض کنید:** آواتار بالای صفحه → *تغییر رمز*

## 🔄 تغییر رمز ادمین روی استقرار Vercel (اگر فراموش شد)

سه راه — مثل هاست اشتراکی:

**۱) از داخل سیستم** (اگر یک ادمین دیگر دارید): کاربران → انتخاب admin → تغییر رمز

**۲) اسکریپت آماده از رایانهٔ شخصی** — چون MySQL از راه دور در دسترس است، همین اسکریپت از کامپیوتر خودتان جواب می‌دهد:
```bash
node scripts/reset-admin-password.cjs "رمز-جدید" "mysql://user:pass@host:3306/db?connection_limit=5"
```

**۳) phpMyAdmin / کنسول دیتابیس** — دستور زیر رمز را به `admin123` برمی‌گرداند (هش ازپیش‌محاسبه‌شده و تست‌شده):
```sql
UPDATE User
SET password='scrypt:628b8dfbae8fdfa3541aeb2c07c65864:568da7c89d59d423032f3d2d0733730df44c3d6d41415c5c86e3c3097dac325e264a201c196185c3971ba6c2bad0345b6f8d379654bff34f473199c441aa5448',
    active=1,
    tokenVersion=tokenVersion+1
WHERE username='admin';
```
> این هش فقط برای رمز `admin123` معتبر است — بعد از ورود فوراً رمز را عوض کنید. اگر مطمئن نیستید ستون `tokenVersion` وجود دارد، اول `ALTER TABLE User ADD COLUMN tokenVersion INT DEFAULT 0;` را اجرا کنید (خطای «Duplicate column» یعنی قبلاً هست — نادیده بگیرید).

## 🔁 دیپلوی‌های بعدی (خودکار)

- هر `git push` به شاخهٔ `main` → Vercel خودکار بیلد و منتشر می‌کند
- هر Pull Request → لینک پیش‌نمایش جدا (Preview)
- برگشت به نسخهٔ قبلی: Vercel → **Deployments** → روی نسخهٔ قبلی ⋯ → *Promote to Production*

## 🌐 دامنهٔ اختصاصی (اختیاری)

**Settings → Domains → Add** → دامنهٔ خود را وارد کنید و طبق راهنما رکوردهای DNS (A/CNAME) را در پنل دامنه تنظیم کنید. HTTPS خودکار صادر می‌شود.

## ⚠️ تفاوت‌ها و محدودیت‌های Vercel (مهم)

| قابلیت | وضعیت روی Vercel | جایگزین |
|--------|------------------|---------|
| کاپی احتیاطی خودکارِ فایل (زمان‌بند) | ✗ غیرفعال (فایل‌سیستم فقط‌خواندنی) | دکمهٔ **«خروجی JSON»** — دانلود مستقیم به رایانه (روشن/خاموش خودکار) |
| ذخیرهٔ کاپی احتیاطی روی سرور + فهرست نسخه‌ها | ✗ | خروجی JSON را در رایانه/درایو ابری نگه دارید |
| بازیابی از فایل JSON (آپلود) | ✓ کار می‌کند | — |
| دانلود `Setup.exe` / `APK` از داخل برنامه | ✗ ۴۰۴ (فایل روی سرور نیست) | فایل‌ها را از رایانهٔ ساخت توزیع کنید یا لینک گیت‌هاب ریلیز بدهید |
| حالت دسکتاپ (SQLite محلی + سینک) | مرتبط نیست — وب همیشه مستقیم MySQL | نسخهٔ دسکتاپ/اندروید مثل قبل کار می‌کند و به همین آدرس جدید وصل می‌شود |
| آدرس IP ثابت سرور | ✗ (IPهای متغیر) | برای Remote MySQL هاست مجبور به باز کردن `%` هستید — رمز قوی بگذارید |

> نکته: روی نسخه‌های دسکتاپ/اندرویدی که به استقرار وب وصل می‌شوند، معماری «محلی‌محور + همگام‌سازی» مثل قبل کار می‌کند؛ فقط آن‌ها به جای هاست قبلی، به آدرس `.vercel.app` وصل می‌شوند.

## 🔧 عیب‌یابی

| مشکل | علت | راه‌حل |
|------|-----|--------|
| بیلد شکست + `P1012 Environment variable not found` | `DATABASE_URL` تنظیم نشده | Settings → Environment Variables → اضافه کنید → redeploy |
| ورود نمی‌شود + خطای اتصال (`P1001 Can't reach database`) | Remote MySQL باز نیست / هاست اشتباه | cPanel → Remote MySQL → `%`؛ نام‌هاست را از پنل هاست چک کنید |
| ورود نمی‌شود + `Access denied` | رمز/نام‌کاربری دیتابیس غلط یا کاراکترهای خاص encode نشده | رمز ساده‌تر بسازید یا URL-encode کنید |
| خطای SSL در اتصال به دیتابیس ابری | سرویس TLS سخت‌گیرانه | `&sslaccept=accept_invalid_certs` را موقتاً تست کنید |
| «خطای دیتابیس» فقط در چند ثانیهٔ اول بعد از دیپلوی | ساخته‌شدن خودکار جدول‌ها هنوز تمام نشده | چند ثانیه بعد دوباره امتحان کنید — خودش ترمیم می‌شود |
| همه کاربران یک‌باره از سیستم بیرون افتادند | تغییر `SESSION_SECRET` نشست‌های قبلی را باطل کرده | طبیعی است — فقط دوباره وارد شوید |
| صفحهٔ ورود باز می‌شود ولی ورود خطای ۵۰۰ | دیتابیس خالی است و بوت‌استرپ نشده | لاگ‌ها: Vercel → پروژه → **Logs** → خطای واقعی را ببینید |

**دیدن لاگ زنده:** Vercel → پروژه → تب **Logs** — همهٔ پیام‌های `[conn]`، `[db]` و `[backup]` همان‌جا هستند.

## 🧪 دیپلوی از ترمینال (روش دوم — بدون گیت‌هاب)

اگر خواستید مستقیم از این رایانه دیپلوی کنید:

```bash
bunx vercel login        # با ایمیل/گیت‌هاب وارد شوید
bunx vercel              # اولین بار: سؤالات لینک را جواب دهید (Add → existing project settings)
bunx vercel --prod       # انتشار نسخهٔ اصلی
```

> متغیرهای محیطی در این روش هم باید از پنل Vercel تنظیم شوند (`bunx vercel env pull` برای استفادهٔ محلی).
